## 结论

2026-10-15 在 tip 部署（forge-agent 约 `87d94b7`）上做 GPU 真实 claim 验收时，本机无状态化主线已过之后，又撞上执行机侧六类问题。每条是「现象 → 方案」，供以后 tip / Thor / PRO5000 联调备查。job **116 PASS**；**117–119** 先 FAIL 再按下列方案修好。job **120** claim=`thor-2231-gpu0`：calib 与 6 个 `mfs://` by-uri 200 为 PASS，compile 因 `RegisterOpAttr` / 整栈 skew FAIL，卡在 aarch64 `tvm-relax-1.1.1-compile` 404，不再单点热补。

本卡只记 tip 部署与 claim 排障，不重述 kb-0029 的本机 MySQL / `mfs://` 主线。

## 问题与方案

### 1) PRO5000 tip「GPU 忙」假忙

- **问题**：tip 进程卡在「GPU 忙」日志，不再 poll；GPU 实际空闲仍假忙。
- **方案**：`restart` tip 进程后恢复。若 GPU 空仍报忙，先查日志时间戳，确认是否卡死在旧状态，再决定 restart。

### 2) Thor tip 缺 `lerobot.common.datasets`

- **问题**：Thor tip 运行时缺 `lerobot.common.datasets`。
- **方案**：把依赖落到 `/work/vendor/lerobot`（deps aarch64 包），标定走 overlay，避免污染系统 Python。

### 3) job118 claim 到旧机

- **问题**：job **118** claim 到旧机 `thor-2240`（`thor-003`），不是 tip 机。
- **方案**：对旧机 `drain`，`schedulable=0`；Thor 侧只保留 tip `thor-2231-gpu0` 可调度。

### 4) LIBERO stats 无 `q01` KeyError

- **问题**：旧机无条件转 assets 时，LIBERO stats 缺 `q01` 触发 KeyError。
- **方案**：tip 路径对无分位数做 skip，改用 checkpoint 的 `norm_stats`，不再依赖旧 assets 分位数字段。

### 5) mlc-vla 版本不对齐

- **问题**：Thor 上 mlc-vla **1.1.0** 缺 `nvfp4_awq_calib`；PRO5000 已是 **1.1.1**。
- **方案**：先热补应急；正式方案须在代码/部署里钉包对齐。说明：aarch64 **1.1.1** 整包当时暂缺，热补不是终态。job 120 表明单点热补不够，见第 6 条。

### 6) Thor compile RegisterOpAttr / stack skew（job 120）

- **问题**：job **120** claim=`thor-2231-gpu0`；validate+calib PASS，6 个 calib artifact 均为 `mfs://` by-uri 200；compile FAIL：`from tvm import relax` 报 `AttributeError`，`tvm.ir._ffi_api` 无 `RegisterOpAttr`。栈为 `tvm-relax-1.1.0-main-9d2dbedcd` + `mlc-vla-1.1.0-main-8f05e9fb9`。
- **根因（流程）**：修 `nvfp4_awq_calib` 只补了 mlc-vla 单点，**未**把 Thor 整栈按 PRO5000 的 tvm-relax+mlc-vla **成套**钉死；tip 沿用 aarch64 1.1.0；验收「缺啥补啥」未做整栈对账。
- **技术根因**：Thor 钉的是 tvm-relax **1.1.0 runtime**（无 `libtvm_compiler.so`）→ `RegisterOpAttr`；PRO5000 是 **1.1.1-compile + mlc 1.1.1** 成套。与 AWQ 缺口同类 skew。
- **方案**：不再单点热补。文件服 aarch64 `mlc-vla-1.1.1` 已有；`tvm-relax-1.1.1-*-compile` aarch64 **404**。有 1.1.0-compile 但不算成套 1.1.1，未上线顶替。当前是 blocker。
- **代码已收**：agent `8ddcfc7`（请求 `-compile` 时 runtime 不得顶替）+ QA_ISSUES #6；Service 仅注释目标 `890539d`。另有此前钉包 fail-fast `59341e7`、QA 清单 `cd57806`。
- **下一步**：文件服发布 aarch64 `tvm-relax-1.1.1-main-9f55f443f-compile` 后，**一次**换钉 `FORGE_STACK` + `pi05-runtime.yaml` `by_arch.aarch64` + claim `stack_lock`（relax 1.1.1-compile + mlc 1.1.1），再喊 QA 开新单。

## Don'ts

1. 勿把「GPU 忙」日志当真实占用而不看时间戳；假忙优先 restart。
2. 勿让旧机（如 thor-2240 / thor-003）继续 `schedulable=1` 抢 tip claim。
3. 勿把热补 mlc-vla 写成已与 PRO5000 永久对齐；须钉包，且勿假定 aarch64 已有正式 1.1.1 整包。
4. 勿在 tip 路径强依赖旧 assets 分位数（`q01`）；无分位数走 ckpt `norm_stats`。
5. 勿再对 Thor tip 做单模块热补；须 PRO5000 vs Thor **成套**对账（tvm-relax-compile + mlc-vla）；勿用 1.1.0-compile 或 runtime 顶替 1.1.1-compile。
