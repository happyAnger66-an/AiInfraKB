## 结论

目标：在 Thor 上打通 **UniRT 包 + ApexInfer** 的 `gr00t_n17` 全链路，并交出与 forge 同机对照的 Apex 耗时。架构师批 **P0→P4**；牛马落地；**2026-10-15** 合入 apexinfer **master `ec7669e`**（`--no-ff` Merge `feat/gr00t-n17-pipeline`，含 glue）。

### CONTRACT / 编排要点

1. **双包双 Executor**：bb + dit 各一 `*_unirt`；对外一个 Session，内部双 Executor。对齐 forge；**不做**合并包。
2. **host glue 在 pipeline**：images/prompt → ViT / tokenize / scatter / rope / masks 全在图外；**勿塞进图**；禁塞 pi05 / 禁 RTC 分叉。
3. **不必 `register_arch`**：有 `function_io` 即可。
4. **对点包锁**：bb=`…_silumul_i4_unirt`；dit=`…_cg4_softadd_unirt`（Thor `/work/gr00t_fp8_phase_a/`）+ DitGemm-C1 so + `TVM_FP8_SMALL_M_TILE=1`。
5. **精度门槛**：overall `cos>0.999` ∧ `mse<0.0005`（站立 gate）。
6. **计时口径**：权威 e2e 以 **lockfreq** stage/business 表为准；**Session 墙钟 ≠ 本表 e2e**；host glue（PT capture）环外 ~1104 ms **不计入** Apex e2e。

### 里程碑数字

| 阶段 | 结果 |

| P0 pack 摸底 | 基线已是 UniRT/`gr00t_n17`；三大缺口（单 model_dir、glue 图外、源 artifact 已清） |

| P4 lockfreq | forge e2e **83.70** / Apex business **83.94**（Δ**+0.24**）；denoise **+2.70** 记已知税；合入不挡 |

### 可泛化

- VLA 推理栈若 forge 已是「双包 + 图外 glue」，Apex 侧应 **镜像编排**（双 Executor + pipeline glue），不要为「一个 model_dir」硬合并包。
- 对点顺序：先 stage dump overall（编排无漂移）→ 再真输入 glue（RoPE 等易漂）→ 最后同机 lockfreq。
- RoPE 漂移：业务≡stage 仍可能 vs PT FAIL；钩 PT rotary 真 cos/sin 钉死后，再把 host glue 对齐同一实现，**勿降 gate**。

## Don'ts

1. 勿做 **合并包**；勿把 glue 塞进图；勿在有 `function_io` 时强推 `register_arch`。
2. 勿把 **Session 墙钟** 或 glue 环外耗时写成 lockfreq **e2e**。
3. 勿用 denoise **+2.70** 挡合或降 overall gate；本轮记税 backlog。
4. 勿未经晓安哥另拍解冻 **FP8 Soft**（含 DitAttnE4 / postC1 等）。
5. 勿把本轮 business **83.94** 写成已冲满 **66.7**（15Hz）；优化暂停，基线仍 +DitGemm-C1 量级。
